# 地図を地図専用の仕組み(MapLibre)に置き換える見積もり

2026-10-21 作成。**未決**(ユーザーが検討中。決まるまで作らない)。今の地図(自前の canvas で毎回全部描く)を、Google マップと同じ作り(倍率ごとのベクトルタイル + GPU で描く)にした場合の作業量・費用・注意点の見積もり。

## 1. 今の作りと、置き換えた後の作り

| | 今 | 置き換え後 |
|---|---|---|
| 描き方 | canvas 2D に毎こま全部を描き直す(`public/app.js` の draw、約 400 行) | MapLibre GL JS が WebGL(GPU)で描く。ドラッグ中は描いた絵を動かすだけ |
| 陸・境界・湖 | 県ごとの JSON を 1 種類の細かさ(約 60 m)で丸ごと読む | 倍率ごとに細かさを変えたベクトルタイル(z4〜z14 ほど)。見えている四角だけ読む。拡大すると元の細かさ |
| 線路・新幹線・海路の道すじ | `rail-paths.json` などを丸ごと読む | 同じくベクトルタイルに入れる |
| 拠点・名前・持ち主の色 | 自前で描く。名前の重なりも自前で判定 | (案 A)今の canvas を地図の上に重ねて残す /(案 B)MapLibre の図形・文字の層にする |
| 拡大縮小・ドラッグ・ピンチ | 自前 | MapLibre の機能 |
| 投影 | 緯度・経度をそのまま平面に(経度だけ縮める) | Web メルカトル(Google マップと同じ)。日本の範囲では見た目はほぼ変わらない |

サーバーの「見ている範囲のタイルを頼む」しくみ(拠点とつながりを送る)は今のまま使える。地図の背景だけがベクトルタイルになる。

## 2. 作業の内訳

作業量は「日」で示す(1 日 = Claude が実装しテストまで通す 1 日分の作業。ユーザーの確認時間は含まない)。

| # | 作業 | 案 A(拠点は今の canvas を重ねる) | 案 B(全部 MapLibre) |
|---|---|---|---|
| 1 | ベクトルタイルを作る道具(`tools/build-tiles.js`)。国土数値情報 N03(行政区域)を間引かない元の細かさで取り直し、陸・境界・湖・線路・新幹線・海路を倍率ごとに間引いて 1 つのファイル(PMTiles)にする。Node だけで動かす(geojson-vt + vt-pbf + pmtiles。Windows で動く) | 2.5 | 2.5 |
| 2 | MapLibre を画面に入れる(ビルド不要のまま `<script>` で読む)。地図の見た目(陸・海・境界・湖・線路の白黒の破線・新幹線の青緑)を今と同じ色で書く | 1.5 | 1.5 |
| 3 | 座標・倍率の置き換え。拡大率で決めている決まり(町・字を出す倍率、縮小表示の段、印と文字の大きさ、見ている範囲のタイルの頼み方)を MapLibre の倍率に合わせ直す | 1.5 | 2 |
| 4 | 拠点の描き方 | 1.5(canvas を地図に重ね、地図が動いたら描き直す) | 5(999 通りの形を画像にして登録、持ち主の色・濃さ・囲みの数字・Lv の札・選択中の点滅を図形と文字の層で。名前の重なりは MapLibre に任せる) |
| 5 | 動く線: 占領した路線の持ち主の色、選んだ拠点のつながり(黒い線)、航路(空路の弧・海路)、町・字のつながり | 1.5 | 2.5 |
| 6 | 地域の支配の色分け(区・市を支配者の色で塗る)、陣地のにじみ | 1 | 1.5 |
| 7 | 操作: 拠点を押して選ぶ、地図から開始地点を選ぶ、引っ越し先を選ぶ、自分の拠点へ戻るボタン | 1 | 1.5 |
| 8 | 確認と直し: パソコン・スマホ(iPhone・Android)、ダークモード、遅い端末。e2e テスト・手順書・説明書・クレジットの更新 | 2 | 3 |
| | **合計** | **約 12.5 日** | **約 19.5 日** |

- 案 A は「背景(陸・境界・線路)」を GPU に任せ、数の少ない拠点だけ今の描き方を残す。重さの大部分(背景)が解決し、拠点の見た目は今とまったく同じにできる
- 案 B は全部が GPU になり一番軽いが、拠点の見た目(999 通りの形・持ち主の色の枠など)を作り直すので長い。名前の出し方(重なりの判定)も MapLibre のやり方に変わる
- お勧めは案 A を先に作り、足りなければ拠点だけ後から案 B に進める(案 A の 1〜3・5〜7 はそのまま使える)

## 3. 費用

| 項目 | 目安 |
|---|---|
| MapLibre GL JS | 無料(BSD-3 ライセンス。画面のクレジットと説明書にライセンス表記を足す) |
| 地図の背景データ | 今と同じ国土数値情報・国勢調査(自前で作るので外の地図サービスの料金はかからない。OSM は使わない) |
| ベクトルタイルのファイル | 全国 z4〜z14 で数百 MB の見込み(作ってみて確定)。App Service の静的ファイルとして配れる(B1 の容量 10 GB の範囲)。転送量が増えたら Azure Blob Storage に置く(月数十〜数百円) |
| 画面が読む量 | MapLibre 本体 約 230 KB(圧縮後)。背景は見ている四角だけ読むので、今の「県ごとの境界 JSON を丸ごと(東京で約 300 KB、北海道で約 1.2 MB)」より少なくなる見込み |

## 4. 注意点・決めること

- **国土数値情報 N03 の取り直し(ダウンロード)が要る。** 今の境界は約 60 m に間引いた後のものしか手元に無い。ダウンロードはユーザーの許可を取ってから
- **文字(日本語)**: MapLibre は名前をタイルの中の字形データで描くのが普通だが、日本語の字形は大きいので、端末の文字(`localIdeographFontFamily`)で描く設定にする。今の BIZ UDPGothic と同じ見た目にはならない場合がある(案 A なら拠点の名前は今のまま)
- **古い端末**: WebGL が使えない端末(かなり古いもの)では地図が出ない。そのときは今の描き方に切り替えるか、対応しないかを決める
- **見た目の細かい差**: 線の太さ・破線の間隔・印の大きさが倍率に対して今と少し違って見える。合わせ込みは 8 の確認で行う
- **作っている間の本番**: 置き換えは別のページ(例: `map2.html`)で作って比べ、よければ切り替える。それまで本番は今の地図のまま

## 5. 今の地図のままできる軽い直し(比較用)

置き換えをしない場合に、同じ不満(重い・粗い)をどこまで減らせるか。

| 直し | 作業量 | 効果 |
|---|---|---|
| ドラッグ中は背景(陸・境界・湖)を 1 枚の絵にしてずらすだけにする | 1.5 日 | ドラッグの重さの多くが減る。止めたときに描き直す |
| 拡大したとき用に細かい境界(約 10〜20 m)を県ごとに作り、拡大したときだけ読む | 1.5 日(N03 の取り直しが要る) | 拡大したときの粗さが減る。データは数倍 |
