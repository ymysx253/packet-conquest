## 1. 概要

| 項目 | 内容 |
|---|---|
| 日本語名称 | パケット陣取り |
| 英語名称 | Packet Conquest |
| ジャンル | ネットワーク学習 × オンライン陣取り対戦(ブラウザゲーム) |
| コンセプト | ネットワークの知識に正解するほど、自分のネットワークが世界中へ広がっていく |
| 対象 | ネットワークを学ぶ学生・社会人。資格試験(IT パスポート、基本情報技術者、CCNA、ネットワークスペシャリストなど)の学習者 |
| 動作環境 | ブラウザ(パソコン・スマホ)。サーバーは Azure App Service |

### 狙い

- **遊びと学習を一致させる**: 知識そのものが操作になる。問題に答える、コマンドを打つことが、そのまま攻撃・防御になる
- **長く遊ばれる(継続率)**: 制限時間のない永続ワールド、やりこみ要素、トラップによる攻防で、毎日戻ってくる理由を作る
- **将来の事業化・M&A を視野に入れる**: 買い手(教育会社、資格団体、セキュリティ企業など)が評価するのは、利用者数・継続率・収益の実績。大人がお金を払う分野(資格・企業研修)に直結させる

## 2. 現状: 試作版 v0.1(実装済み)

部屋コード制、4分間の対戦。**永続ワールドに作り替える前の検証用**。

### 実装済みの機能

- 部屋コードで最大6人(ボットを含む)が対戦。ホストが開始し、ボットを追加できる
- 日本とその周辺の簡略化した地図(15拠点、20リンク)。拠点の種類は DC(1点)・GW(海底ケーブルの陸揚げ拠点、2点)・IX(相互接続点、3点)
- 自分の拠点とつながった拠点を攻撃、自分の拠点を防御強化(Lv 最大3)。防御 Lv が高いほど問題が難しい(難易度1〜3)
- サブネット計算の4択問題を**プログラムで自動生成**(マスク、ネットワークアドレス、ブロードキャスト、ホスト数、同一ネットワーク判定)。答えは計算で求めるので常に正確。解答後に解説を表示
- 不正解で4秒間操作不可
- 切断後60秒以内なら同じプレイヤーとして再接続できる(合言葉はタブごとに sessionStorage へ保存)
- 路線図風の画面。自分の陣地が「路線」のように色でつながる。ライト・ダーク両対応、スマホでは地図が横スクロールし、開始時に自分の拠点を表示

### 技術構成

| 役割 | 使用技術 |
|---|---|
| サーバー | Node.js 20 以上、`http` + `ws`(WebSocket、パス `/ws`) |
| 画面 | HTML / CSS / JavaScript(Canvas で地図描画)。ビルド不要 |
| 状態 | サーバーのメモリ上(再起動で消える) |
| 配置 | Azure App Service(Linux、Node 20 LTS、B1 以上推奨) |

### ファイル構成

```
server/index.js            HTTP 配信 + WebSocket 中継、定期処理(1秒ごとの tick、25秒ごとの ping)
server/room.js             部屋・得点・攻撃/防御・ボット(フェーズ1で world.js に作り替える)
server/map/japan.js        地図データ(拠点・リンク・隣接表・開始地点)
server/questions/subnet.js 問題の自動生成(サブネット計算)
public/            画面(index.html, style.css, app.js)
test/check.js      問題3万問を計算し直して答えを検証
test/e2e.js        実サーバーに2人で接続し1試合を通す
```

### 既知の制約

- 状態がメモリにあるため、**インスタンスは1台**でしか動かない。再起動で世界が消える
- ログインなし。プレイヤーは部屋ごと・タブごとの一時的な存在
- Azure では WebSocket を有効にし、Always On を推奨(README 参照)

## 3. 確定した仕様(次の版で実現する)

### 3.1 永続ワールド

- **制限時間なし**。全世界のネットワークを、すべてのプレイヤーが一つの世界で取り合い続ける
- ゲームを始めると、**選んだ開始地域に自分専用のノードが新しく生まれ**、近くの地域拠点とつながる。そこから広げていく
- プレイヤーが増えるほど、世界のネットワークも大きくなる

### 3.2 難易度は10段階

| Lv | 内容 | 難易度 |
|---|---|---|
| 1 | 問題に解答(4択) | ★☆☆☆☆☆☆☆☆☆ |
| 2 | 時間制限つきで解答(4択、15秒) ※残すかは未決 | ★★☆☆☆☆☆☆☆☆ |
| 3 | 答えを入力して解答(選択肢なし) | ★★★☆☆☆☆☆☆☆ |
| 4 | 連続で正解(2問連続) | ★★★★☆☆☆☆☆☆ |
| 5 | 経路表(ルーティングテーブル)を読み、次の転送先を答える | ★★★★★☆☆☆☆☆ |
| 6 | トラップを見抜く(設定情報を読んでハニーポットか本物かを判定。罠を攻撃すると自分の拠点を1つ失う) | ★★★★★★☆☆☆☆ |
| 7 | コマンドで到達確認(`ping` / `tracert` を打ち、結果を読んで通れない場所を特定) | ★★★★★★★☆☆☆ |
| 8 | ファイアウォール突破(ACL を読んで抜け道を見つけ、通れるポート・送信元を指定するコマンドを入力) | ★★★★★★★★☆☆ |
| 9 | 経路を作って突破(`route add` などで迂回経路を設定) | ★★★★★★★★★☆ |
| 10 | 複合トラップを制限時間内に突破(ハニーポット + ファイアウォール + 経路遮断) | ★★★★★★★★★★ |

### 3.3 場面とレベルの対応

| 場面 | レベル |
|---|---|
| 開始地域の、誰のものでもないノード | 1〜3 |
| 他のプレイヤーの陣地 | 4〜6 |
| トラップが仕掛けられたノード | 7〜9 |
| 防御を固めきった地域の中心 IX | 10 |

守る側は、正解して得たポイントでハニーポット・ファイアウォールなどのトラップを自分のノードに仕掛けられる。オフライン中の守りがトラップの主な役割になる。

### 3.4 コマンド系(レベル7〜10)

- **制限時間あり**。目安: Lv7 90秒 / Lv8 120秒 / Lv9 150秒 / Lv10 180秒(数値は調整可)
- 時間切れは「逆探知された」扱い
  - 突破失敗。しばらくそのノードを攻撃できない
  - 守る側に「◯◯さんが侵入を試みました」と通知
  - Lv10 の失敗のみ、自分のノードを1つ失うなど重めのペナルティ
- **コマンドはすべて手で打ち込む。コマンドを選ぶボタンは作らない**(ユーザーの明確な方針: リアルに打ち込むことが、ハッカー感・ゲーム性・教育につながる)
- 本物のターミナルにある **Tab 補完**と **↑ キーの履歴呼び出し**は入れる方向(提案済み、ユーザーから異論なし。実装前に再確認するとよい)
- コマンドの書き方は、実務・資格試験で使う本物(`ping`, `tracert`/`traceroute`, `ipconfig`, `nslookup`, `route`, ACL の記法など)に合わせる
- コマンド系は**パソコン推奨**と画面で明示する。スマホは主にレベル1〜6と陣地の見張り用

### 3.5 安全面の方針(必ず守る)

- ターミナルは**ゲーム内の架空ネットワークだけで動く模擬環境**。実在のシステムには一切つながらない
- 地図やつながり方は実在を参考にしてよいが、**攻撃対象になる会社・機器は架空の名前**にする
- **実在サーバーのアドレスは載せない**
- 本物のシステムに使える攻撃手順は教えない。仕組みの理解と守り方の習得を重視する(学校・企業に導入してもらうためにも重要)

## 4. 未決事項(実装前にユーザーと決める)

1. 開始地域は自分で選ぶか、自動で割り当てるか
2. 個人戦か、陣営(チーム)制か(Ingress 型の陣営は初心者が入りやすい)

10. 拠点をすべて失ったときの再開方法(開始地域に再生成する案)
11. 終わりがない中での目標(週・月ごとのランキング、地域の支配率など)
12. ログイン方式

## 5. 技術方針(永続ワールド版)

| 課題 | 方針案 |
|---|---|

| 配置 | 引き続き Azure App Service |

## 6. 背景メモ(企画時の調査)

### 類似ゲームと差別化

- 最も近いのは **ThreatGEN: Red vs Blue**(Steam)。攻撃側・防御側に分かれてネットワークの支配権を奪い合うターン制の教育ゲーム。ただしクリック操作中心で、細かい技術は教えないと明記されている
- ほかに Hacknet(1人用ストーリー型)、hackmud / Grey Hack(娯楽寄りのハッキング MMO)、Bitburner(放置系)、TryHackMe / Hack The Box(ゲームではなく学習サービス)
- **差別化**: ブラウザですぐ遊べる・大人数・知識そのものが操作になる・コマンドを本物どおり手で打つ・日本語で日本の資格試験に直結。この組み合わせの既存ゲームは見つからなかった

### 参考にした成功例・失敗例

- Wordle(NYT が買収)、Agar.io(Miniclip)、Krunker.io(FRVR)、Kahoot!(投資ファンドが取得)など。共通点は、すぐ遊べる、ルールがすぐ分かる、自然に広まる、戻ってくる理由がある
- **Draw Something**(Zynga が買収後すぐに人気が落ちた)と **fly.pieter.com**(AI で数時間で作り一時は大きな売上、その後急減と報道)は、一時的な人気より継続率が大事だという教訓

### 8.5 フェーズ1の実装手順(案)

1. **拠点マスターと地図**(済 2026-10-12): `server/map/tokyo.js` に東京周辺29拠点のマスター(緯度・経度・種類・Lv・点数)。`server/map/geo.js` が描画座標への変換と、近い3拠点を結ぶリンクの自動生成を行う。検証は `test/map.js`。吉祥寺は遠すぎて中心が潰れるため外した。中心部が密なので、画面側にズームとパンが必要(手順6で対応)
2. **永続ワールド**(済 2026-10-12): `server/world.js`。部屋・4分タイマー・ボットを廃止し、世界は1つ。参加すると東京駅から 2.5 km 以内に自分専用の拠点が生まれ、近い2拠点とつながる。拠点マスターは起動時に store から読み、空なら `tokyo.js` でシード。手順3の復帰コード、手順7の初心者保護(24時間・3拠点以下)と全滅時の再生成(暫定)も最小限入れた。画面は緯度・経度から自分で投影。検証は `test/world.js`、E2E は `test/e2e.js`
3. **プレイヤーと復帰コード**: ニックネーム + 復帰コードで端末をまたいで同じプレイヤーに戻れる
4. **難易度 Lv1〜4**: Lv1 4択 / Lv2 15秒4択 / Lv3 入力式 / Lv4 2問連続。中立拠点は拠点マスターの Lv、他人の陣地は Lv4
5. **保存(Cosmos DB)**: `server/store.js`。起動時に読み込み、変更時に書き込む。手元はエミュレーターまたは保存なしで動く
6. **差分配信**: 接続時に全体、以後は変化分のみ。画面側も差分を受けて更新。(地図の拡大縮小・移動は 2026-10-12 に先行して実装済み)
7. **初心者保護・距離による防御上限・全滅時の再生成(暫定)**
8. **ランキングと支配率の表示**、画面の文言を永続ワールド向けに更新
9. **テスト**: 入力式の答えの判定、拠点マスターの検証(重複・座標範囲・Lv範囲)、E2E を永続ワールド向けに書き直す
10. **Azure**: Cosmos DB アカウント作成、接続文字列をアプリ設定へ、デプロイして確認


### 8.6 問題の供給方式(2026-10-12 ユーザー方針)

**場所ごとに問題が決まっている。** 供給の仕方はレベルで分ける。

| レベル | 供給方式 | 内容 |
|---|---|---|
| Lv1〜4 | その場で自動生成(現行方式) | サブネット計算など、計算で答えが決まる問題。拠点ごとの架空ネットワーク(10.x.0.0/16)を使って出題し、毎回変わる |
| Lv5〜10 | **固定問題を DB に保存** | 経路表・トラップ判定・コマンドシナリオなど。拠点ごとに用意し、**誰かがクリアしたら差し替える**。クリアされなくても**定期的に更新**する |

- 差し替えの理由: 答えの共有を防ぐ。クリアした人が答えを広めても、次の挑戦者には別の問題が出る
- 固定問題の作り方(案): 構造は固定のテンプレートにし、IP アドレスやポート番号などの値は生成時にランダムに決めて保存する。保存前に検証プログラムで答えを確認する。テンプレートは AI で下書きし人が確認(第5章の方針どおり)
- Cosmos DB に `questions` コンテナーを置く。項目: 拠点 id、レベル、本文(シナリオ)、答え(複数可)、解説、状態(active / cleared / expired)、作成日時、期限
- フェーズ1(Lv1〜4)では固定問題を使わないが、**問題の取得口を「生成」と「DB」の2系統に分けておき**、`questions` コンテナーの形だけ先に決める

未決(フェーズ2で決める): 拠点1つあたりの固定問題の本数、定期更新の間隔(週1など)、固定問題を拠点専用にするか共有プールに拠点の情報を差し込むか、検証の担当

### 8.7 拠点の登録(2026-10-12 ユーザー方針)

**拠点はどんどん追加できる。** Google マップに場所を登録するように、将来は利用者や事業者が拠点を登録できるようにする。登録された拠点も占領されれば誰かの支配下になる。

- **登録機能そのものはまだ先**。ただし、その仕組みと DB 設計はフェーズ1のうちに用意する
- 設計への影響
  - 拠点マスターはコードのファイルではなく **DB(Cosmos DB の `nodes` コンテナー)に持つ**。`server/map/tokyo.js` は初期データ(シード)として DB に流し込む役に変える
  - 拠点の項目: id(自動生成)、名称、種類、緯度・経度、Lv、点数、状態(公開 / 審査中 / 非公開)、登録者、登録日時、架空ネットワーク(自動で割り当て)、所有者(占領者)、防御 Lv、トラップ
  - 「登録者」と「所有者(占領者)」は別の項目。登録した人が守りやすいわけではない
  - **リンクは座標から自動生成**(すでにこの方式)。拠点が増えても地図が壊れない。近い拠点とつなぐ処理は、DB から読み込んだあとにサーバーで行う
  - **描画座標は画面側で計算**する。サーバーは緯度・経度を送り、画面がズーム・パンに合わせて投影する(拠点が増えて範囲が広がっても作り直しが要らない)
  - Cosmos DB の地理空間クエリ(位置と距離)を使えるよう、位置は GeoJSON の Point で保存する
  - 登録時の審査(不適切な名称、実在の攻撃対象になりうる施設の除外、重複)が必要。3.5 の安全方針に沿う審査基準は登録機能を作る時に決める
- 未決(登録機能を作る時に決める): 誰が登録できるか(ログイン必須か)、審査を人が行うか自動か、登録した拠点の Lv と点数の決め方、登録数の上限、営利利用(事業者が自社の拠点を出す)の扱い

拠点マスターのファイル(2026-10-14): `server/map/data/<region>.json`。項目は id(英小文字・数字・ハイフン)、name、kind、area(区・市)、lat、lon、level(1〜3)、value(1〜5)、tags(任意)。`server/map/load.js` が起動時に検証し、おかしければ止まる。DB 化したらこのファイルがシードになり、登録機能はこの項目に status / registeredBy / owner などを足したものを DB に書く。画面上の拠点の形は難易度で変える(Lv1 円、Lv2 角丸四角、Lv3 六角形、5点の拠点は星、プレイヤーの拠点は小さい円)

8.5 の手順への反映: 手順1の `tokyo.js` はシードデータに役割を変える。手順5(保存)で `nodes` に拠点マスターと状態を一体で保存し、起動時に DB から読む。手順6の画面側で緯度・経度から投影する

### 8.8 レベル体系と拠点の形(2026-10-14 ユーザー方針)

- 拠点のレベルは **1〜999**。1〜10 が基本で、**国はレベル 10**。11 以上は将来の拡張用に形だけ先に用意する
- 画面に最初に出るのは自分の見えている範囲。**東京の拠点は Lv1〜5**(都道府県・地方・国はその上のレベル)
- **原則(2026-10-14 決定)**: 難易度が上がるほど巨大組織・重要拠点なので大きくしてよいが、**模様は必ず変える(重複禁止)**。`test/shapes.js` で Lv1〜999 がすべて異なる模様であることを検証する
- 描き方(`public/shapes.js`): 1 の位 = 本体の形(10 種)。10 の位 = 0〜4 は白抜きで外輪 0〜4 本、5〜9 は黒塗り(実際は所有者の色)で外輪 0〜4 本。100 の位 = 外枠の種類(1 ギザギザ、2 波線、3 点線、4 二重線、5 太線、6 ギザギザ+二重線、7 波線+二重線、8 点線+二重線、9 ギザギザの太線)。Lv11 以上はレベル番号の札も付ける。一覧は `shapes.html`

| Lv | 形 | 問題(設計書 3.2) |
|---|---|---|
| 1 | 円 | 4択 |
| 2 | 角丸四角 | 15秒4択 |
| 3 | 三角形 | 入力式 |
| 4 | ひし形 | 2問連続 |
| 5 | 五角形 | 経路表 |
| 6 | 六角形 | トラップ判定 |
| 7 | 星(5点) | コマンド: 到達確認 |
| 8 | 星(6点) | コマンド: ファイアウォール |
| 9 | 星(8点) | コマンド: 経路作成 |
| 10 | 二重の星(国) | 複合トラップ |

- 点数は当面レベルと同じ値(東京: Lv1=1点 … Lv5=5点)
- 他プレイヤーの陣地を攻めるときの難易度は、拠点のレベルと 4 の大きい方
- **暫定**: Lv4 以上の問題はまだ無いので、実装されるまでは Lv3 相当の生成問題を出し、画面に「暫定」と表示する(Lv4 は手順4、Lv5 はフェーズ2、Lv6 以降はフェーズ2〜3で本実装)

### 8.9 拠点の形の拡張案(2026-10-14 ブレスト。10 の位の黒塗りと 100 の位の外枠は 8.8 に採用済み。特殊形は未決)

形は「層を重ねる文法」として作る。各層が独立しているので、桁や属性を増やしても同じ仕組みで描ける。

| 層 | 役割 | 候補 |
|---|---|---|
| 本体の形 | 1 の位 | 円、角丸四角、三角形、ひし形、五角形、六角形、星5、星6、星8、二重の星(いま実装済み) |
| 塗り | 10 の位の上半分(5〜9)など | 白抜き / 黒塗り(実際は所有者の色で塗る。中立は黒、ダークテーマは白) |
| 外輪 | 10 の位 | 0〜4 本。二重線を何本も重ねる |
| 外枠の種類 | 100 の位 | ギザギザ(歯車)、波線、点線、二重線、太線、およびその組み合わせ。外輪の間にギザギザを挟むのも可 |
| 特殊形 | レベルとは別の属性 | ハートなど 3 種ほど。イベント拠点・登録者の特別な拠点・季節限定などに使う案 |
| 札 | 補助 | Lv 番号。小さく描くときの保険 |

- 上限は 999 に広げた(拠点マスターの検証も 999 まで)
- 一覧ページには 100〜999 は百の位ごとに見本を数個ずつ載せる
- 決めること: 特殊形(ハートなど)を何に使うか、外輪の間にギザギザを挟むような追加の層を使うか

### 8.10 レベル分けの定義(2026-10-14)

レベル 1〜999 を操作方式の帯に分けた。帯の定義と、分野別の題材一覧は **`docs/LEVELS.md`** にある(たたき台。未決事項は同ファイルの第3章)。
要点: 1〜10 選択 / 11〜100 入力 / 101〜200 コマンド / 201〜300 機器設定 / 301〜400 複数拠点 / 401〜500 クラウド / 501〜700 解析・診断 / 701〜900 複合パズル / 901〜999 伝説級。Lv500 以上は専門家・ハッカー級。
高レベル帯は守る側の解析と架空環境のパズルに限り、本物に使える攻撃手順は扱わない(3.5)。
