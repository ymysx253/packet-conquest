# レベル整理のたたき台

作成: 2026-10-19。**同日、第 3 章の案でレベルを設定した**(ユーザー決定)。決め方は `tools/levels.js`、今あったデータは `tools/migrate-levels-v2.js` で一度だけ移した。
**2026-10-23 に出題のレベルは 1〜100 にまとめると決まった**(第 7 章)。ここの数字(実際に拠点に付いているのは 1〜777。999 まで使ったことはない)は、それまでの拠点の「格」の記録として残す。拠点の格 → 1〜100 の出題レベルの対応はまだ決めていない(ゲームは当面この文書の番号で出題している)

拠点は 11 万件を超えたが、基礎レベルはほとんどが Lv1〜5 に集まっている。レベル(1〜999)の幅を拠点の重みに合わせて使い直すための材料。基準は「国 = Lv777」(2026-10-19 ユーザー提示)。

## 1. 前提(いまの決まり)

- **拠点のレベル = 出題の難しさ**。出題レベル = 基礎レベル + 強化の段数(`LEVELS.md` 第 3 章)。Lv700 の拠点なら Lv700 の問題(700〜799「解析と診断」)を出す
- レベルは 100 ごとに知識の領域が決まっている(`LEVELS.md` 第 2 章)

| レベル | 領域 |
|---|---|
| 1〜99 | アドレッシングと基礎 |
| 100〜199 | L2・L3 の動作 |
| 200〜299 | サービスのしくみ |
| 300〜399 | セキュリティの基礎と設定 |
| 400〜499 | ルーティングと機器設定 |
| 500〜599 | 複数拠点の設計 |
| 600〜699 | クラウド |
| 700〜799 | 解析と診断 |
| 800〜899 | 複合(攻略と防御) |
| 900〜999 | 伝説(総合) |

- **ゲームが今出せる問題は、この番号で Lv1〜30 と Lv51〜60 だけ**。ほかのレベルは Lv10 までの問題で代わりに出している(仮の問題の印つき)。新しい 1〜100 の問題(第 7 章)はできているが、まだゲームにつないでいない
- 突破に要る正解の回数は、レベルではなく線の本数で決まる(DESIGN.md 第 14 章)。レベルを変えても回数は変わらない
- 強化の段数は 1 日ごとに 1 下がる
- 「国 777」は 2026-10-17 に一度決め、2026-10-18 に「地域は拠点ではなく配下の集まり」と決めたときに廃止した数字(都道府県 100〜299、地方 400〜599、大陸 888、天体 950、宇宙 999 も同時に廃止)。国そのものは拠点ではないので、今回は **拠点のレベルを割り付けるときの物差し**として使う案にしている(第 4 章 #1)

## 3. たたき台(国 = 777 を一番上の物差しにした割り付け)

国の象徴を 777 に置き、そこから下へ段を割り付ける案。出題の領域(第 1 章)とも意味が合うようにした。

| 段 | 件数 | いま | 案 | 出題の領域(案のとき) |
|---|---|---|---|---|
| 国の象徴(国会議事堂) | 1 | 30 | **777** | 解析と診断 |
| 首都の象徴(東京都庁) | 1 | 15 | 600 | クラウド |
| 国際線の拠点の空港 | 7 | 10 | 500 | 複数拠点の設計 |
| 都道府県庁舎(47 にそろえる) | 7 → 47 | 15 | 400 | ルーティングと機器設定 |
| 各県で一番の城・塔 | 47 | 10 | 300 | セキュリティの基礎と設定 |
| 各県で一番の空港 | 28 | 8 | 250 | サービスのしくみ |
| 主要駅(東京駅・新宿駅 など) | 23 | 4〜5 | 200 | サービスのしくみ |
| ほかの空港 | 53 | 5 | 150 | L2・L3 の動作 |
| 乗り換え駅・港・有名な名所 | 1,430 | 2〜5 | 30〜99(乗り入れ路線・知名度で) | アドレッシングと基礎 |

| 町・字 | 101,598 | 1 | **1〜9**(人口などで) | アドレッシングと基礎 |

この案だと:

- 始めたばかりの人は町・字(Lv1〜9)から始め、駅(Lv10〜)に進む。開始地点の「Lv1 の駅と町・字」の決まりは「Lv1〜9 の町・字」などに直す必要がある
- 大きな拠点ほど、強化しなくても最初から難しい問題になる。強化は「その上に積む」もの
- **Lv100 以上の問題はまだ作れない**。割り付けを先に入れると、当面は Lv10 までの問題で代わりに出る(仮の印つき)。問題の生成器ができた順に本物の問題に替わる

## 4. 設定した内容(2026-10-19)

- 第 3 章の案のとおり。町・字は人口で Lv1〜9、乗り換え駅は路線の数で 30〜99、名所は知名度で 15〜70、港は 30〜70
- 都道府県庁舎: 47 にそろえる方針で 39 道府県 + 東京都庁を入れた。岐阜・静岡・島根・奈良・愛媛・高知・山形の 7 県は、Wikidata に座標が無く、国土数値情報の「国・都道府県の機関」は非商用なので未登録
- **問題の無いレベルの拠点は占領できない**(ユーザー決定)。線はつながっていて選べるが、問題が出ない。強化も、上げた先のレベルに問題があるときだけ(問題の無いレベルまで上げて誰にも攻められなくするのを防ぐ)。いま問題があるのは Lv1〜30 と Lv51〜60
- 開始地点: 「Lv1 の駅と町・字」を「町・字(Lv1〜9)と、ふつうの駅(Lv10)」に言い換えた(指す範囲は同じ)
- 縮小表示の段ごとの下限: 段 1 は Lv30、段 2 は Lv100、段 3 は Lv400(2026-10-19 に 250 から上げた。日本全体では都道府県庁舎・都庁・国会議事堂・国際線の拠点の空港だけ)、段 4 は Lv400
- 777 は「国の象徴の拠点(国会議事堂)」に使った(第 4 章 #1 の (a))
- 観光地(同日追加): 世界遺産・日本三景・特別名勝 300、各都道府県で一番 150、指定・百選あり 30〜70、ほか 15〜25(`docs/tourism/README.md`)

## 6. 決めてもらったこと(記録)

1. **777 の意味**: (a) 国の象徴の拠点(国会議事堂)を 777 にする(第 3 章の案)、(b) 国そのもの(地域)の難しさの目安として表示や称号にだけ使う、(c) ほか
2. **段の数字**: 第 3 章の「案」の列を直す
3. **町・字のレベル**: すべて Lv1 のままか、人口・面積・つながりの本数などで Lv1〜9 に分けるか
4. **開始地点の決まり**: 「Lv1 の駅と町・字」を、新しいレベルに合わせてどう直すか(例: Lv9 以下の町・字と Lv10 の駅)
5. **都道府県庁舎**: 47 都道府県すべてを拠点にするか
6. **入れる時期**: すぐ割り付ける(問題は当面仮のもの)か、問題の生成器が追いつくのを待つか

## 見直しの案(2026-10-22。B 案の「格と出題レベルを分ける」方向で 2026-10-23 に出題レベルを 1〜100 にした。格 → 出題レベルの変換表はまだ。第 7 章)

突破の回数を √(つながりの本数) にした(DESIGN.md 2026-10-22)のと同時に、レベルの付け方を見直す案を出した。数字は公開・占領できる拠点 114,103 件で数えたもの。いま問題があるのは Lv1〜30 と Lv51〜60。

**今の問題**

- 取れない拠点が 458 件: 空港 88 件すべて(空路 538 本が使えない)、庁舎・都庁・国会議事堂 48 件すべて、城・世界遺産など 104、主要駅(Lv200)23、4 路線以上の駅 130、知名度の高い名所約 65。地図を縮小したときに見える拠点(Lv100 以上・400 以上)はほぼ全部取れない
- 隣どうしで難しさが急に上がる(Lv10 の駅のすぐ隣が Lv30 の VLSM 総合。港 512 件はすべて Lv30)
- 作った問題があまり出ない(拠点の基礎レベルは 1〜10・15・25・30・60 だけ。11〜14、16〜24、26〜29、51〜59 は強化したときだけ)
- 強化は 1 日 1 回答えれば下がらず、どの拠点も Lv30 で止まる(強い人の陣地が Lv30 だらけになる)
- レベル 1 つの数字に、難しさ・点数・縮小表示・名札・印の大きさ・名所の線の本数まで持たせている

**案**

| 案 | 中身 | 新しく要る問題 |
|---|---|---|
| A. 縮める | レベルを 1〜30 に縮める(町 1〜9、駅 10、名所 11〜20、港 15、空港 20〜27、庁舎 28、国会 30 など) | 0。ただ縮小表示などもレベルで決めているので、結局「目立ち度」を別に作ることになる |
| **B. 格と出題レベルを分ける(お勧め)** | 今の数字(国会 777 など)は「格」として点数・縮小表示・名札・並び順・線の本数に使う。出題レベルは格から変換表で引き、今ある問題の範囲に収める(例: 町 1〜9 → 1〜9、駅 10 → 10、名所 → 11〜20、主要駅 200 → 23、城・世界遺産 300 → 25、庁舎 400 → 27、国際空港 500 → 28、都庁 → 29、国会 777 → 30)。問題が増えたら表を伸ばすだけ | 0 |
| C. 地域で段階 | 区・市の都心の度合いで出題レベルに +0 / +5 / +10。A か B と組み合わせる前提。住む場所で不公平になる | 0 |

**どの案にも足せる手直し(強化)**: 強化の上限を「基礎 + 10」などにする / 強化しても減り始めの時刻を戻さない / 上限に着いたら回数を +1(「強化は回数を変えない」の決定を変える) / 問題の無いレベルを飛ばす

**ほかの案**: 1 つの拠点に段の幅(例 21〜30)を持たせ、何回かの正解を段の下から順に出す(1 回の占領で階段を上がれる)

**決めること**

1. 格と出題レベルを分けるか(B)、1 つの数字のまま縮めるか(A)
2. いちばん上(国会など)の出題を Lv30 にするか、強化の余地を残して Lv25 ぐらいにするか
3. 点数を格(777 など)のままにするか、差を縮めるか(順位・チームの人数の段とのつり合い)
4. 印の形と大きさは難しさで決めるか、格で決めるか
5. 強化の上限と下がり方を変えるか
6. 地域の段階(C)や段の中で順に出す方式を、あとで足すか

## 7. 2026-10-23 からの状況(出題レベル 1〜100)

- **出題レベルは 1〜100**(2026-10-23 ユーザー決定。`LEVEL-LIST.md` 第 12 章、`DESIGN.md` 決定の記録)。段は 入門 1〜15・初級 16〜35・中級 36〜60・上級 61〜78・専門 79〜89・神 90〜100。1 レベルに LEVEL-LIST の項目が話題ごとにいくつか入り、同じレベルの中で問題の種類が入れ替わる(`server/questions/cl/level100-map.json` → `tools/build-level100.js` → `level100.json`、取得口 `getLevelQuestion`)
- **2026-10-26 に変更(ユーザー決定): 格はなくす。** 拠点のレベルは 1〜100 だけにし、出題・画面の「Lv」・点数・印・縮小表示の段・名札・並び順を全部それで決め直す。この文書の 1〜777 の数字は、レベルを付け直すまでの記録
- **点数**(2026-10-26 ユーザー決定): 1 拠点の点 = 四捨五入(k × 1.05^レベル)、最低 1 点。k は公開の拠点を全部取った合計がおよそ 100 万点になる数(いま約 0.855)。Lv1〜10 は 1 点、Lv35 5 点、Lv60 16 点、Lv78 38 点、Lv89 66 点(`DESIGN.md` 決定の記録)
- **問題のできている数**(2026-10-25): LEVEL-LIST の 361 項目のうち 284。1〜89 のうち 81 レベルに少なくとも 1 つ問題がある(`docs/LEVEL-TABLE.md`)。残りは構成図・設定・模擬ターミナルの仕組みが要る項目(`docs/questions/DIAGRAM-CONFIG.md`)と、神レベル 90〜100

  3. 強化の上限と下がり方(見直しの案の手直し)。地図を 3 つに分けた(`docs/MAPS.md`)ので、強化があるのは個人戦マップとチーム戦マップだけ
  4. 個人マップの出題レベル(全員が真ん中から始め、最初の 2 拠点は特例で 1。それ以外は格から引く変換表をそのまま使うか)
