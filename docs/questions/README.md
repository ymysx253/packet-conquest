# 問題設計書(Lv11〜100)の読み方

作成: 2026-10-18。`docs/LEVELS.md` 未決 #9「Lv11〜100 の問題を先に設計する」の成果物。2 人の担当が同時に書いた 2 冊の設計書と、その共通部分を 1 つに統合した仕様書の 3 冊からなる。題材の階段(`LEVELS.md` 第 4 章)と `DB.md` は変えていない。コードもまだ変えていない。

## 1. 3 つのファイルの役割と読む順

| 順 | ファイル | 役割 | 読む人 |
|---|---|---|---|
| 1 | `COMMON.md` | **共通仕様**。問題オブジェクトの拡張(`answerKind` / `fields` / `compare` / `verifier`)、入力欄の UI、正規化の規則(format ごと)、複数欄の判定、seed 付き乱数と固定問題の保存の形、誤答・defenseNote・安全規則・検証テストの流儀、共通部品のファイル一覧、共通部分の「決めてもらうこと」。第 0 章に 2 冊の差異と決定の一覧がある | 土台(手順 1)を作る人、全員 |
| 2 | `design-11-50.md` | Lv11〜50(アドレス計算・VLSM・種別と到達性・カプセル化の追跡)を 1 レベルずつ: 題材・形式・生成・パラメータ・誤答・検証・例題。生成器と固定テンプレートの一覧、迷った点 | 11〜50 の生成器を作る人 |
| 3 | `design-51-100.md` | Lv51〜100(トランスポート・DHCP/DNS・経路表・ACL と NAT・観測からの逆算・MAC 学習)を 1 レベルずつ、同じ構成。ゲーム内の規則(NAPT の付け替え、DHCP のアドレス、AD 値、ACL の処理順)は各章の冒頭 | 51〜100 の生成器を作る人 |

- 2 冊の設計書の表・例題は書いた当時の名前のまま。実装で使う名前は `COMMON.md` のもので、読み替え表が各設計書の冒頭(11-50 は 0.2、51-100 は第 1 章)にある(例: `int` → `number`、`cidr4` → `ipv4cidr`、`term` → `token`、問題直下の `format` / `inputHint` → `fields[0]`)
- 「生成器」「固定テンプレート」「シナリオ生成器」の用語は `COMMON.md` 5.1。方式の定義は `LEVELS.md` 第 5 章

## 2. 実装順(両設計書の実装順を依存順にマージしたもの)

各ステップは「生成器 + 検証テスト + `index.js` への登録(`MAX_IMPLEMENTED` を上げる)」を 1 単位とし、`npm.cmd test` に追加してから次へ進む。終了条件: 該当レベルの検証テストが 1 万件(FactBank は全数)通り、画面で解けること。

| 順 | 作るもの | 理由(1 行) |
|---|---|---|
| 1 | **土台**: `rng.js`、`normalize.js` + `test/normalize.js`、`fields` 付きの問題形式、`world.ask` / `world.answer` の choice/text 両対応、`server/index.js` の `inputs` 検査、画面の入力欄(複数欄)と `tables`(COMMON 第 9 章) | Lv11 以上の全レベルがここに依存する。できるまで Lv11 以上は暫定(COMMON 第 10 章 10) |
| 2 | **11〜20** `calc.js` + `test/calc.js` | 純計算で依存が最少。複数欄(`fields`)の最初の実例 |
| 3 | **21〜30** `vlsm.js` + `test/vlsm.js`(`compare: 'set'` を判定器に足す) | 集合比較の実例。配置の規則(大きい順に先頭から)は Lv99 の `prefixplan` と `plan-verifier` がそのまま使う |
| 4 | **51〜60** `transport.js` + `test/transport.js`(55〜60 の計算生成) | 純計算。既存 `toIp` / `buildOptions` を再利用し、`addrport` の最初の実例。NAPT の付け替え規則はここで固定(81〜90 が使う) |
| 5 | **71〜80** `routing.js` + `test/routing.js`(71・72・75〜80) | Lv7 `routeTable` の拡張で既存コードに近い。`ifname` の最初の実例 |
| 6 | **31〜40** `kinds.js` + `facts.js` + FactBank(`data/facts/`)+ `vocab.json` + **安全リンタ** `lint.js` + `test/kinds.js` | FactBank・固定テンプレート・`token` 語彙表の最初の実例。人が書く文章(FactBank)が入るので安全リンタを同時に入れる |
| 7 | **81〜90** `aclnat.js` + `test/aclnat.js`(81〜84・86〜90) | 6 の FactBank(Lv85)とリンタ、4 の NAPT 規則(Lv89)に依存。Lv9 `aclEval` とは別の評価器で検証 |
| 8 | **41〜50** `server/sim/netgen-min.js` + `forward-min.js` + `hops.js` + `test/hops.js` | 最小 NetGen / シミュレータ(#9・#10)の最初の実例。表を複数持つ `tables` を使う。91〜98 の土台になる |
| 9 | **61〜70** `dhcpdns.js` + `test/dhcpdns.js` + FactBank(61・62・65・66) | 計算は独立だが固定テンプレートが 4 つあり人確認を待つので後ろ。拠点名からホスト名(`.example`)を作る(COMMON 第 10 章 5 の決定が要る) |
| 10 | **91〜100** `diagnose.js`(95・99 の計算生成 → 91〜94・96〜98 のシナリオ生成器)+ `l2switch.js`(100)+ `plan-verifier` + `test/diagnose.js` / `test/l2switch.js` | 8 のシミュレータを ACL・NAT・DNS 照合まで広げたうえで、独立検証器(8 種の原因を総当たり)を先に書き、生成器を後に書く(plant-then-perturb) |
| 11 | **固定化**(#5 #11 #13): `questions` コンテナーへの (templateId, seed, generatorVersion) + `rendered` + `answer` の保存、拠点 × レベルで active 1 つ、クリアで seed 差し替え、`npm.cmd run questions:gen`(`tools/questions-gen.js`)、保存前にリンタ | COMMON 第 10 章 1(その場生成か保存か)の決定後。どの段からでも後付けできるので最後 |

残る固定テンプレートの FactBank(51〜54・73・74・85)は 6 と 7 の間で下書きと人確認を進める。各段は独立して配信できる(`MAX_IMPLEMENTED` を 20 → 30 → 60 → 80 → 40 → 90 → 50 → 70 → 100 と、実装した段の上限に合わせて上げる。飛んだ段は `index.js` が「最も近いもの」を出す既存の仕組みのまま)。

## 3. 判断に迷った点(両設計書の一覧を重複をまとめて 1 つにしたもの)

出典: 11-50 = `design-11-50.md` 第 9 章の番号、51-100 = `design-51-100.md` 第 8 章 (d) の番号。「共通」は `COMMON.md` 第 10 章にも推奨付きで載せたもの。

### 共通仕様に関わるもの

| # | 内容 | 推奨 | 出典 |
|---|---|---|---|
| 1 | **その場生成か保存か**。計算生成は正確さの点ではその場生成で動くが、`DESIGN.md` 3.5「拠点に紐づき、クリアまで同じ問題」に従うなら保存が要る。(a) seed だけ保存し本文は再生成、(b) DB.md 3.4 どおり `rendered` も保存。`LEVELS.md` 未決 #8 と一緒に決める | Lv11 以上は一律 (b)。固定問題を「解き直し」にできる | 11-50 #12、51-100 #13(共通 1) |
