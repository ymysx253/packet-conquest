# 学ぶことの一覧(カリキュラムの下書き)

作成: 2026-10-22。**下書き。未決**(決めるのはユーザー)。この一覧をもとに、レベルの付け方と問題を決め直すための材料。

---

## 1. 目的と並べ方

- このゲームで学べるのは、ネットワークの「言葉 → しくみ → 計算 → 読む → 設定する → 設計する → 診断する」まで。いちばん簡単な「ネットワークとは」から、複数の拠点とクラウドをまたぐ設計・診断までを 1 本の順番に並べた
- 公開されている試験の出題範囲の **項目名と順番** を参考にした(第 8 章の (d))。文章は写さず、自分の言葉で短く書いた
- 5 段に分ける: **入門 → 初級 → 中級 → 上級 → 専門**
- **らせん状に並べる**: どの分野(アドレス、L2・L3、サービス、セキュリティ、運用・診断 …)も、入門ではことばと役割だけ、初級で 1 段の計算や表、中級で自分で組み立てる、上級で複数の仕組みの組み合わせ、専門で設計と総合、と段ごとに少しずつ深める。1 つの分野を最後まで掘ってから次へ進むことはしない
- 入門・初級を厚くした(ゲームの入り口なので、10〜20 秒で答えられる 4 択が作れる項目を多く)

### LEVELS.md との違い

| | LEVELS.md(今) | この一覧 |
|---|---|---|
| 並べ方 | 分野ごとの縦積み(1〜99 アドレス、100〜199 L2・L3、200〜299 サービス …) | らせん(どの段にもいろいろな分野がある) |
| Lv1 の中身 | サブネットの計算 | 「ネットワークとは」「機器の名前と役割」など、計算の前の基礎 |
| スイッチの基本 | Lv100 から(その前に VLSM の設計 Lv21〜30 を通る) | 入門で役割、初級で MAC アドレステーブル。VLSM は中級 |
| 無線・ケーブル・回線の計算 | 置き場所が無い(LEVELS.md 1〜99 の末尾) | 入門・初級に入れた |

## 2. 表の見方

- **番号**: 通し番号。学ぶ順番
- **段**: 入門 / 初級 / 中級 / 上級 / 専門
- **分野**: 基礎(ネットワーク全体の考え方と数)、物理・無線、アドレス、L2・L3、ルーティング、サービス、セキュリティ、運用・診断、設計、クラウド・自動化
- **問題の形**: このゲームの画面で出せる形
  - 4 択: 選ぶ(いまの画面でできる)
  - 入力: 値を打つ(いまの画面でできる)
  - 表を読む: 表や図を見て、4 択か入力で答える(いまの画面でできる)
  - 並べ替え: 順番を答える(**いまの画面には無い**。入力で「3-1-4-2」と打つ形なら今でもできる)
  - 模擬ターミナル: コマンドを手で打ち、出力を読んで答える(**まだ無い**)
  - 設定を書く: 機器の設定を書き、意味で判定する(**まだ無い**)
- **今ある問題**: 今の生成器(Lv1〜30、Lv51〜60)でまかなえるなら、その Lv。無ければ「無し」
- **LEVELS**: LEVELS.md でいちばん近いレベルの段。どこにも無いものは「—」

## 7.5 ヒントと説明の出し方(2026-10-22 の案。一部決定)

ヒントや説明を出すかどうかで難しさが大きく変わるので、「難しさを調整するつまみ」として段ごとに減らしていく(足場かけ)。問題を作り直さなくても段差が付く。

| 段 | 説明・ヒント |
|---|---|
| 入門 | 問題の前に説明カードをいつも出す(知らなくても読めば解ける) |
| 初級 | 「ヒント」ボタンで計算の手順や式を見られる(例: /26 は 256 ÷ 4 = 64 個ずつ) |
| 中級 | ヒントは最初の 1 手だけ(例: まずブロックの大きさを出す) |
| 上級から | ヒントなし。答えたあとの解説だけ |

- **決定(2026-10-22 ユーザー)**: ヒントを使った正解も、正解として 1 回に数える(減らさない)。学ぶことがいちばん大事なので、「使って覚える」を勧める
- **決定(2026-10-22 ユーザー)**: ヒントを使えるのは中立の拠点を攻めるときと、自分の拠点を強化するときだけ。**ほかの人(チームの持ち物を含む)の拠点を攻めるときは使えない**(取り合いは実力勝負)
- ヒントは課金アイテムにしない(お金で問題がやさしくなるのは `BILLING.md` 第 1 章の「お金で釣り合いを崩さない」に反する)
- 出題の形の案(未決): 最初の数問は ○× か 3 択、入門は 4 択、初級は 4 択と入力を混ぜる(同じ分野で選ぶ → 入力)、中級からは入力と表・図を読む。間違えたら同じ考え方の別の数字の問題をすぐ出す。入力はスマホ向けに(IP アドレスは 4 欄・数字のキーボード、2 進数は 8 個の切り替えボタン)。入門の拠点はお手付きを短く(例 2 秒)。1 か所の中で 4 択 → 入力と形を混ぜる。図をタップして答える問題は手間が大きいので後回し

### (c) この一覧から出題レベルを決め直すときの考え方(案。決めるのはユーザー)

- **案 1: 通し番号の順に出題レベルを振る**。#1 → Lv1、#2 → Lv2 …。いちばん素直だが、155 項目に 999 の幅は広すぎるので、1 項目に何レベルかを持たせる(例: 入門の 1 項目 = 1 レベル、上級・専門は 1 項目 = 10〜50 レベル)
- **案 2: 段ごとにレベルの帯を決め、帯の中は通し番号順**。例: 入門 1〜50、初級 51〜150、中級 151〜300、上級 301〜600、専門 601〜999。拠点の格(町・字、駅、名所、空港、庁舎 …。`LEVEL-PLAN.md` の B 案)を帯に当てる
- **案 3: LEVELS.md の 100 ごとの分野はそのまま、各分野の頭に入門・初級の項目を足す**。今の決まり(100 の位 = 分野 = 印の外枠)を崩さないが、Lv1 から順に遊ぶ人はやはり 1〜99 のアドレスだけを長く通る
- どの案でも、今の生成器は新しい番号へ付け替えるだけで使える(`server/questions/index.js` のレベル → 生成器の表を直す)。固定問題は テンプレート id・seed・版 で保存する前提なので、レベルの番号が変わっても問題そのものは変わらない
- `LEVEL-PLAN.md` の B 案(格と出題レベルを分ける)と組み合わせやすい。格は今の数字のまま、出題レベルをこの一覧の順で引く
- 決めること: 段の数と名前、段ごとの帯の幅、1 項目に何レベルを持たせるか、LEVELS.md を書き直すか並べて置くか、印の外枠(100 の位)の意味を残すか
